# Smart Factory — ส่งต่องาน AMR ให้ Database และ Dashboard

อัปเดต 22 พ.ย. 2026 จาก Woray ให้ผู้ดูแล Database และ Dashboard รับช่วงซอร์ส ทดลองระบบ และเก็บผลทดสอบของ AMR ทั้งชุด เริ่มจาก Node-RED AMR Lab บนเครื่องพัฒนา แล้วใช้ผลที่ผ่านแล้วประกอบการทดสอบใน Lab

[คู่มืออ่านโค้ดและทดสอบระบบ AMR](../amr-system-guide.md) อธิบายวิธีเปิด MATLAB และทดสอบด้วยตัวเอง ผลศึกษา 5 คลิป และกรณีทดสอบจองทางร่วมที่เสนอสำหรับรอบถัดไป

## ฟีเจอร์และซอร์สที่ส่งมอบ

Save Mission — ลากเส้น ปรับจุดจอด และบันทึกภารกิจรายคัน** | มีต้นแบบเส้นตรงและเส้นโค้งใน [Route Editor UI](../../dashboard/web-app/curve-preview.html) และ [Node-RED flow](../../database/node-red/amr-lab/amr-route-editor.flow.json) ส่วน [Route Lab](../../robotics/amr/route-lab/README.md) แปลงเป้าหมายเป็นพิกัด MiR และตรวจ Forbidden Zone ก่อนส่ง ทดสอบการย้ายต้นทาง/ปลายทาง จุดโค้งอิสระ และกรณีรถอยู่ห่างจุดเริ่ม งานบันทึกลงฐานกลางให้เก็บเส้นที่วางไว้ จุดจอดที่ยืนยัน และรอยวิ่งจริงโดยเชื่อมกับภารกิจเดียวกัน | เบราว์เซอร์และ Node-RED Route Editor, Database สำหรับข้อมูล Mission, แผนที่ที่สอบเทียบและ MiR API สำหรับทดสอบกับรถจริง |

| **3. Tap-to-Go — เลือกรถ แตะปลายทาง และให้ระบบหาเส้นทาง** | มี [Tap-to-Go UI](../../dashboard/web-app/tap-to-go.html), [ตัววางแผน](../../robotics/amr/route-lab/tap-to-go-planner.cjs), [Node-RED flow](../../database/node-red/amr-lab/amr-tap-to-go.flow.json) และ [Map Reference flow](../../database/node-red/amr-lab/floor9-reference.flow.json) ทดสอบเส้นทางอ้อมประตูปิดในโหมดจำลองแล้ว รอตรวจ LiDAR สด การสอบเทียบ ระยะเผื่อขนาดรถ และกรณีไม่มีทางผ่าน | Dashboard ในเบราว์เซอร์, Node-RED และ Map Reference สำหรับจำลอง, MATLAB สำหรับรันทดสอบ API, MiR พร้อม LiDAR และแผนที่ที่สอบเทียบเมื่อลองกับรถจริง |
| **4. Map Zones & Points — เพิ่มโซนและจุดใช้งาน** | มี [Floor 9 Reference](../../robotics/amr/route-lab/maps/floor9/README.md) และ [ตัวอย่างข้อมูล Forbidden Zone](../../robotics/amr/route-lab/route-zones.example.json) เป็นฐานสำหรับพัฒนาหน้าเพิ่ม/แก้ไข **โซนอันตราย โซนชะลอ โซนห้ามเข้า จุดจอด และจุดชาร์จ** บันทึกโซนและจุดแยกตามแผนที่และรุ่นของแผนที่ก่อนนำมาใช้วางเส้นทาง | Dashboard สำหรับวาด/แก้ไข, Node-RED API และ Database สำหรับบันทึก, Map Reference, MiR API และแท่นชาร์จสำหรับตรวจจุดจริงใน Lab |
| **5. Fleet Schedule — คาดการณ์เวลาถึง A, B, C ของ AMR แต่ละคัน** | เป็นงานต่อยอด ให้ Dashboard แสดงเวลาโดยประมาณรายคันและรายจุด เช่น AMR 2 คาดว่าจะถึง B เวลา 14:20 และแสดงเวลาถึงจริงเมื่อมีข้อมูล ทดสอบคิว ชาร์จ และช่วงทางร่วมกับ AMR 3, 4 และ 5 คัน แสดง Gantt และเทียบแผนภายใต้เงื่อนไขเดียวกัน สำหรับ OCC ให้ยืนยันสูตรก่อนรายงานคะแนน | Node-RED และ Database สำหรับภารกิจ สถานะ คิว และเวลาจริง, MATLAB สำหรับจำลองและเทียบเวลาของแต่ละแผน, Grafana หรือ Dashboard สำหรับตาราง/Gantt, ML สำหรับปรับประมาณเวลารอและเวลาถึงเมื่อมีประวัติเพียงพอ |
| **6. Save Workflow — บันทึกแผนงานทั้งชุดของ AMR หลายคัน** | เป็นงานต่อยอดจาก Save Mission ผู้ใช้ตั้งชื่อแล้วเก็บ Mission ที่กำหนดให้รถแต่ละคัน รวมเงื่อนไขและสถานการณ์ของแผน เช่น Workflow หนึ่งให้ AMR 1 ไปชาร์จและอีกสองคันทำงาน ส่วนอีก Workflow ใช้สองคันเพราะอีกคันอยู่ระหว่างซ่อม รอบแรกให้บันทึกและเปิดแผนกลับมาตรวจได้ การเปิดแผนมีไว้ดูหรือแก้ไขก่อนผู้ใช้เลือกขั้นตอนถัดไป | หน้า Save/Load Workflow บน Dashboard, Node-RED API และ Database สำหรับเก็บแผนและรุ่น, MATLAB สำหรับลองเทียบแผนในสถานการณ์เดียวกัน, ML เป็นทางเลือกเสริมเพื่อประมาณเวลาหรือช่วยจัดอันดับแผนจากข้อมูลย้อนหลัง |

**การใช้ MATLAB, ML และ LLM** — MATLAB จำลองเหตุการณ์และเทียบแผนในฟีเจอร์ 5–6 โดยใช้เงื่อนไขเริ่มต้นเดียวกัน เช่น จำนวนรถที่พร้อม งานที่รอ และคิวชาร์จ ในฟีเจอร์ 6 ให้ผู้ใช้เลือกเกณฑ์ก่อนเทียบ เช่น จบงานเร็วหรือรอคิวน้อย แล้วแสดงเหตุผลและผลจำลองให้ผู้ใช้เลือกเอง ML ใช้เรียนรู้เวลารอและเวลาถึงจากข้อมูลจริงและนำค่าประมาณไปช่วยเทียบแผนเมื่อผ่านการประเมิน ส่วน LLM ใช้อ่านและอธิบายสถานะหรือ ETA ล่าสุดผ่าน LINE โดยมีเวลาอัปเดตกำกับ การแจ้ง Alarm ยังใช้เงื่อนไขของ Node-RED

**เกณฑ์สำหรับฟีเจอร์ 4** — ทดสอบเพิ่ม แก้ไข และเปิดกลับมาเห็นโซนและจุดบน Map รุ่นเดิม ให้ระบบแยกความหมายของโซนอันตราย โซนชะลอที่มีเพดานความเร็ว และโซนห้ามเข้าที่ใช้ปิดเส้นทาง ตรวจว่าจุดจอดและจุดชาร์จอยู่ในพื้นที่ที่เข้าถึงได้ การส่งค่าลงรถจริงต้องตรวจชนิดโซน พิกัด และความสามารถของรถแต่ละคัน

**เกณฑ์สำหรับฟีเจอร์ 6** — เก็บชื่อและรุ่นของ Workflow, รุ่นแผนที่, รายการรถที่เข้าร่วม, Mission รายคัน, ลำดับหรือเงื่อนไขระหว่างงาน และสถานการณ์ชาร์จ/ซ่อม/บำรุง เปิดกลับมาเทียบอย่างน้อยหนึ่งแผนที่ใช้รถครบกับอีกแผนที่ใช้สองคัน และแสดงว่ารถคันใดพร้อมทำงาน ณ เวลาที่เปิดแผนนั้น

## ความรับผิดชอบของทีมรับช่วง

- **[Database](database.md)** เป็นเจ้าของข้อมูลและการทดสอบระบบตั้งแต่ Node-RED ถึง Dashboard ดูแลรุ่นของ Map, Zone, Mission และ Workflow ใช้ MATLAB ทดสอบ API และจำลองการเดินรถหลายคัน ส่วน Simulink ใช้เมื่อจะจำลองการเร่ง เบรก หรือการตอบสนองของตัวควบคุม เก็บการรายงานสถานะ การขอจอง การยืนยัน และการคืนสิทธิ์ผ่านช่วงทาง เพื่อทวนเหตุการณ์ได้เมื่อข้อมูลมาช้าหรือรถออฟไลน์ รับผิดชอบการทดสอบ ML, LLM และ Alarm ร่วมกับ Dashboard
- **[Dashboard](dashboard.md)** ดูแล Grafana และหน้าจอ Node-RED แสดงรถทุกคันจาก Map Reference เดียวกัน ดูตำแหน่ง สถานะ ภารกิจ เวลาอัปเดต เส้นที่วางและรอยวิ่งจริง รับช่วงหน้าแก้โซนและจุด ตารางเวลาถึงรายจุด และหน้าเปิด/บันทึก Workflow รวมถึงการแสดงผลเมื่อข้อมูลค้างหรือ query ไม่พบข้อมูล
- **สัญญาข้อมูลร่วม** ระบุ `robotId`, `missionId`, `mapId`, `referenceId`, กรอบพิกัด, เวลาที่รถรายงาน และเวลาที่ระบบรับ ใช้ `workflowId` และรุ่นของ Workflow สำหรับแผนที่บันทึก ใช้ `runId`, `planId`, `resourceId`, เวลาเริ่ม–จบ และ `source` สำหรับผลจำลอง/เหตุการณ์จริง เก็บรุ่นแผนที่กับประวัติเหตุการณ์ เพื่อเปิดดูรอบเดิมได้เมื่อแผนที่เปลี่ยน
- **Robotics / ผู้ควบคุม Lab** ยืนยันเฟิร์มแวร์ แผนที่ พิกัด ขนาดตัวรถ ระยะเผื่อและวิธีหยุดฉุกเฉินก่อนทดสอบจริง ทดสอบบนรถจริงเฉพาะรอบที่ผู้ควบคุม Lab อนุมัติ

| สภาพแวดล้อม | สิ่งที่ใช้ |
|---|---|
| ต้นแบบ | เครื่องพัฒนา, Docker Compose, Node-RED 5.0.8, เว็บเบราว์เซอร์, Node.js สำหรับสร้าง flow จากซอร์สและรันทดสอบ |
| จำลอง | MATLAB พร้อมสิทธิ์ใช้งาน ทดสอบกับ R2026b แล้ว ใช้ Simulink และสิทธิ์ของเครื่องมือนั้นเพิ่มเมื่อต้องสร้างแบบจำลองการเคลื่อนที่ระดับตัวรถ |
| Database / Dashboard | InfluxDB และ Grafana จากชุดที่ทีมใช้, สิทธิ์อ่าน/เขียนของแต่ละบริการ และข้อมูลสถานะจำลองหรือประวัติ AMR |
| Lab | AMR/MiR ตามจำนวนที่ทดสอบ, เครือข่าย Lab, LiDAR/ข้อมูลสิ่งกีดขวางจากรถ, สิทธิ์เข้าถึง API ที่ตรงกับรุ่นรถ และแผนที่นำทางของแต่ละคัน ตรวจขนาดรถและช่องผ่านจริงพร้อมผู้ควบคุม |
| ML / LLM / LINE | ข้อมูลรอจริงสำหรับประเมินโมเดล, บัญชี LINE Messaging API และ webhook สำหรับทดสอบ, สิทธิ์เรียกโมเดล LLM ที่ทีมเลือก เก็บโทเคนและกุญแจในระบบ credentials ของเครื่องทดสอบ |

## เปิด Node-RED และรันทดสอบซ้ำ

รันจาก root ของ repo

```sh
docker compose -f database/node-red/amr-lab/compose.yaml up -d
node --test robotics/amr/route-lab/route-zones.test.cjs
```

เปิด [Node-RED Editor](http://127.0.0.1:1884/) แล้วลอง [Route Editor](http://127.0.0.1:1884/amr/route-editor), [Joystick](http://127.0.0.1:1884/amr/joystick), [Tap-to-Go](http://127.0.0.1:1884/amr/tap-to-go) และ [Floor 9](http://127.0.0.1:1884/amr/floor9/map) ใน Docker volume ใหม่ ระบบโหลดต้นแบบทั้งสี่แท็บและ [flow ของทีม](../../database/node-red/flows.json) ในสถานะ Disabled สำหรับตรวจใน Editor สำหรับ Node-RED เครื่อง Lab ให้สำรอง flow ปัจจุบันก่อน แล้ว Import เฉพาะไฟล์ในตารางที่ต้องใช้ โดยนำ Map Reference เข้า runtime เดียวกับ Tap-to-Go และตรวจแท็บ/พาธซ้ำก่อน Deploy

จาก MATLAB เปิดโฟลเดอร์ `simulation/amr` ใน repo แล้วรัน [สคริปต์ทดสอบ MATLAB → Node-RED](../../simulation/amr/check_matlab_node_red.m)

```matlab
check_matlab_node_red
```

ผลยืนยันล่าสุดจาก MATLAB R2026b บน Windows ใช้ `floor9-clean-plan-v1` กับ AMR จำลอง 1 คัน เปิดประตู D-11 ได้ 657 px และปิด D-11 ได้ 807 px โดย MATLAB batch คืน exit code 0

ก่อนส่งมอบทดสอบ Route Lab กับ MiR API จำลองผ่าน 1 ชุด ครอบคลุมการปฏิเสธเป้าหมายที่ไม่ผ่านการตรวจใน Preview และ Submit ก่อนเขียนข้อมูล และตรวจว่า Route Editor, Joystick, Tap-to-Go, Floor 9 และ Map Catalog ตอบ HTTP 200 บน Node-RED พอร์ต 1884

| ลำดับทดสอบต่อ | หลักฐานส่งกลับ |
|---|---|
| **Map Zones & Points** บันทึกโซนทั้งสามชนิดและจุดจอด/จุดชาร์จ แล้วเปิดกลับจาก Map รุ่นเดิม | ภาพ Overlay และผลทดสอบว่าเส้นทางอ้อมโซนห้ามเข้า โซนชะลอมีค่าความเร็วที่ตรวจได้ และจุดจอด/ชาร์จเข้าถึงได้ |
| **Fleet simulation** ให้รถหลายคันขอใช้ประตูพร้อมกัน ปิดประตูระหว่างวางแผน ทำให้สถานะรถหนึ่งคันค้าง และทดสอบทางแคบ/วงกวาดประตูบานพับ | Log ตำแหน่งและคิวรายคัน ช่วงจองทาง เวลารอ การเปลี่ยนเส้นทาง และผลตรวจว่าช่วงห้ามใช้ร่วมกันไม่ทับกัน |
| **Fleet Schedule และ ML เวลารอ AMR** บันทึกเวลาเข้าคิว เวลาได้ใช้ทางร่วม และเวลาถึง A/B/C พร้อมจำนวนรถในคิวและสถานะประตู ประเมินค่าทำนายเทียบกับค่ามัธยฐานบนข้อมูลคนละช่วงกับชุดฝึก | ตารางเวลาตามแผน เวลาถึงโดยประมาณพร้อมเวลาอัปเดต เวลาถึงจริง และความคลาดเคลื่อน ระบบจองทางใช้สถานะจริง ทดสอบแขน UR และการทำนาย OCC ภายหลัง |
| **Save Workflow** บันทึกแผนที่มีรถชาร์จและแผนที่มีรถซ่อมหรือบำรุง เปิดกลับมาทีละรุ่นและลองนำไปเทียบใน MATLAB | รายการ Mission และรถตรงกับแผนที่บันทึก การเปิดแผนไม่มีคำสั่งเคลื่อนรถ และมีผลเปรียบเทียบตามเกณฑ์และสมมติฐานที่ระบุ |
| **LINE Alarm และ LLM** ให้ Node-RED ส่ง Alarm จากเหตุการณ์จำลอง และให้ LLM ตอบคำถามสถานะจากข้อมูลที่ Node-RED อ่านได้ ทดสอบข้อมูลสด ข้อมูลค้าง และ ID รถที่ไม่มี | ตัวอย่าง Alarm หนึ่งเหตุการณ์พร้อมเวลาที่ส่ง ตัวอย่างคำตอบที่ระบุรถและเวลาอัปเดต และกรณีข้อมูลไม่พอ ยืนยันว่าเส้นทางของ LLM เปิดใช้อ่านสถานะอย่างเดียว |
| **Backup / Restore** โหลดชุด Floor 9 จาก Git ลงสภาพแวดล้อมแยกและ import Map Reference flow | เทียบ `referenceId` ขนาดภาพ ตำแหน่งวัตถุ และผล Tap-to-Go ก่อน–หลัง พร้อมบันทึกรุ่นที่กู้คืน |
