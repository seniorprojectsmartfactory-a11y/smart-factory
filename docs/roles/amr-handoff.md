# Smart Factory — ส่งต่องาน AMR ให้ Database และ Dashboard

อัปเดต 22 พ.ย. 2026 จาก Woray ให้ผู้ดูแล Database และ Dashboard รับช่วงซอร์ส ทดลองระบบ และเก็บผลทดสอบของ AMR ทั้งชุด เริ่มจาก Node-RED AMR Lab บนเครื่องพัฒนา แล้วใช้ผลที่ผ่านแล้วประกอบการทดสอบใน Lab

## ฟังก์ชันและซอร์สที่ส่งมอบ

| ฟังก์ชัน | โค้ดและสถานะ | เกณฑ์สำหรับคนรับช่วง |
|---|---|---|
| **1. ลากเส้นภารกิจ ปรับจุดจอด และบันทึก** | [Route Editor UI](../../amr-route-lab/curve-preview.html) และ [Route Editor flow](../../node-red/amr-lab/amr-route-editor.flow.json) เป็นต้นแบบเส้นตรงและเส้นโค้ง และมี [Route Lab](../../amr-route-lab/README.md) สำหรับแปลงเป้าหมายเป็นพิกัด MiR และตรวจ Forbidden Zone ก่อนส่งภารกิจ | ลากจุดเริ่มและจุดจบ แทรกจุดโค้งได้อิสระ และทดสอบกรณีรถเริ่มอยู่ห่างจุดแรก ตรวจการเก็บเส้นที่วางไว้ จุดจอดที่ยืนยัน และรอยวิ่งจริงให้เปิดกลับมาดูได้แยกกัน ฐานกลางสำหรับข้อมูลภารกิจและการเข้าไปรับเส้นทางจากจุดเริ่มยังต้องตรวจต่อ |
| **2. เลือก AMR และใช้ Joystick ช่วยระหว่างภารกิจ** | [Joystick UI](../../amr-route-lab/joystick-preview.html) และ [Joystick flow](../../node-red/amr-lab/amr-joystick.flow.json) มี AMR จำลองสามคันและเลือกควบคุมทีละคัน | สลับคันแล้วคำสั่งไปที่คันที่เลือก ทดสอบปล่อยมือ ขาดการเชื่อมต่อ หมดสิทธิ์ควบคุม และการพัก/กลับไปทำภารกิจเดิม การขับ MiR จริงแบบต่อเนื่องยังรอยืนยันช่องทางที่รุ่นและเฟิร์มแวร์ใน Lab รองรับ |
| **3. Tap-to-Go และแผนที่กลาง** | [Tap-to-Go UI](../../amr-route-lab/tap-to-go.html), [ตัววางแผน](../../amr-route-lab/tap-to-go-planner.cjs), [Tap-to-Go flow](../../node-red/amr-lab/amr-tap-to-go.flow.json) และ [Map Reference flow](../../node-red/amr-lab/floor9-reference.flow.json) ใช้ผังชั้น 9 จำลองการแตะจุดหมายและการอ้อมประตูที่ปิด | ทดสอบจุดบนกำแพง/บันได ปิดประตูแล้วอ้อมหรือคืนสถานะไปไม่ได้ และตรวจระยะเผื่อขนาดรถ แบบจำลองปัจจุบันใช้กริดพิกเซลและสถานะประตูจำลอง งานจัดการหลาย Map/ชุด Object จากแผนเดิม การสอบเทียบ และข้อมูล LiDAR สดยังต้องทดสอบต่อ |
| **4. Fleet Schedule / Simulation และเทียบแผนด้วย OCC** | มีผังข้อมูลและ API จำลองเป็นจุดตั้งต้น และมี [สคริปต์ทดสอบ MATLAB → Node-RED](../../node-red/amr-lab/check_matlab_node_red.m) ที่ทดสอบ Tap-to-Go ของรถหนึ่งคัน ข้อกำหนดจัดคิวหลายคัน จองช่วงทาง และเทียบแผน A/B ยังต้องพัฒนาและทดสอบ รวมถึง Gantt และสูตร OCC | จำลอง 3, 4 และ 5 คัน ให้แต่ละคันส่งสถานะและให้ระบบจัดลำดับการผ่านทางร่วม ใช้เหตุการณ์เดียวกันสร้าง Gantt และเทียบแผนภายใต้เงื่อนไขเดียวกัน บันทึกข้อมูลที่ใช้คำนวณ OCC และยืนยันสูตรกับอาจารย์ก่อนรายงานคะแนน |

ฟังก์ชัน 5 พักไว้ก่อน ส่วน Alarm, ML และ LLM อยู่ในรายการทดสอบร่วมของระบบด้านล่าง

## ความรับผิดชอบของทีมรับช่วง

- **[Database](database.md)** เป็นเจ้าของข้อมูลและการทดสอบระบบตั้งแต่ Node-RED ถึง Dashboard ใช้ MATLAB ทดสอบ API และจำลองการเดินรถหลายคัน ส่วน Simulink ใช้เมื่อจะจำลองการเร่ง เบรก หรือการตอบสนองของตัวควบคุม ให้เก็บเหตุการณ์การส่งสถานะของรถ การขอจอง การยืนยัน และการคืนสิทธิ์ผ่านช่วงทาง เพื่อทวนได้ว่าระบบจัดคิวถูกต้องแม้ข้อมูลมาช้าหรือรถออฟไลน์ รับผิดชอบการทดสอบ ML, LLM และ Alarm ร่วมกับ Dashboard
- **[Dashboard](dashboard.md)** ดูแล Grafana และหน้าจอ Node-RED แสดงรถทุกคันจาก Map Reference เดียวกัน ดูตำแหน่ง สถานะ ภารกิจ เวลาอัปเดต เส้นที่วางและรอยวิ่งจริง แสดงคิวและเวลารอโดยประมาณ รวมถึงผลจำลอง กรณีข้อมูลค้าง และกรณี query ไม่พบข้อมูล
- **สัญญาข้อมูลร่วม** ระบุ `robotId`, `missionId`, `mapId`, `referenceId`, กรอบพิกัด, เวลาที่รถรายงาน และเวลาที่ระบบรับ ใช้ `runId`, `planId`, `resourceId`, เวลาเริ่ม–จบ และ `source` สำหรับผลจำลอง/เหตุการณ์จริง เก็บรุ่นแผนที่กับประวัติเหตุการณ์ เพื่อเปิดดูรอบเดิมได้เมื่อแผนที่เปลี่ยน
- **Robotics / ผู้ควบคุม Lab** ยืนยันเฟิร์มแวร์ แผนที่ พิกัด ขนาดตัวรถ ระยะเผื่อและวิธีหยุดฉุกเฉินก่อนทดสอบจริง ทดสอบบนรถจริงเฉพาะรอบที่ผู้ควบคุม Lab อนุมัติ

## อุปกรณ์และซอฟต์แวร์

| สภาพแวดล้อม | สิ่งที่ใช้ |
|---|---|
| ต้นแบบ | เครื่องพัฒนา, Docker Compose, Node-RED 5.0.8, เว็บเบราว์เซอร์, Node.js สำหรับสร้าง flow จากซอร์สและรันทดสอบ |
| จำลอง | MATLAB พร้อมสิทธิ์ใช้งาน ทดสอบกับ R2026b แล้ว ใช้ Simulink และสิทธิ์ของเครื่องมือนั้นเพิ่มเมื่อต้องสร้างแบบจำลองการเคลื่อนที่ระดับตัวรถ |
| Database / Dashboard | InfluxDB และ Grafana จากชุดที่ทีมใช้, สิทธิ์อ่าน/เขียนของแต่ละบริการ และข้อมูลสถานะจำลองหรือประวัติ AMR |
| Lab | AMR/MiR ตามจำนวนที่ทดสอบ, เครือข่าย Lab, LiDAR/ข้อมูลสิ่งกีดขวางจากรถ, สิทธิ์เข้าถึง API ที่ตรงกับรุ่นรถ และแผนที่นำทางของแต่ละคัน ตรวจขนาดรถและช่องผ่านจริงพร้อมผู้ควบคุม |
| ML / LLM / LINE | ข้อมูลรอจริงสำหรับประเมินโมเดล, บัญชี LINE Messaging API และ webhook สำหรับทดสอบ, สิทธิ์เรียกโมเดล LLM ที่ทีมเลือก เก็บโทเคนและกุญแจในระบบ credentials ของเครื่องทดสอบ |

## เปิด Node-RED และรันทดสอบซ้ำ

รันจาก root ของ repo

```sh
docker compose -f node-red/amr-lab/compose.yaml up -d
node --test amr-route-lab/route-zones.test.cjs
```

เปิด [Node-RED Editor](http://127.0.0.1:1884/) แล้วลอง [Route Editor](http://127.0.0.1:1884/amr/route-editor), [Joystick](http://127.0.0.1:1884/amr/joystick), [Tap-to-Go](http://127.0.0.1:1884/amr/tap-to-go) และ [Floor 9](http://127.0.0.1:1884/amr/floor9/map) ใน Docker volume ใหม่ ระบบโหลดต้นแบบทั้งสี่แท็บและ [flow ของทีม](../../node-red/flows.json) ในสถานะ Disabled สำหรับตรวจใน Editor สำหรับ Node-RED เครื่อง Lab ให้สำรอง flow ปัจจุบันก่อน แล้ว Import เฉพาะไฟล์ในตารางที่ต้องใช้ โดยนำ Map Reference เข้า runtime เดียวกับ Tap-to-Go และตรวจแท็บ/พาธซ้ำก่อน Deploy

จาก MATLAB เปิดโฟลเดอร์ `node-red/amr-lab` ใน repo แล้วรัน

```matlab
check_matlab_node_red
```

ผลยืนยันล่าสุดจาก MATLAB R2026b บน Windows ใช้ `floor9-clean-plan-v1` กับ AMR จำลอง 1 คัน เปิดประตู D-11 ได้ 657 px และปิด D-11 ได้ 807 px โดย MATLAB batch คืน exit code 0

ก่อนส่งมอบทดสอบ Route Lab กับ MiR API จำลองผ่าน 1 ชุด ครอบคลุมการปฏิเสธเป้าหมายที่ไม่ผ่านการตรวจใน Preview และ Submit ก่อนเขียนข้อมูล และตรวจว่า Route Editor, Joystick, Tap-to-Go, Floor 9 และ Map Catalog ตอบ HTTP 200 บน Node-RED พอร์ต 1884

| ลำดับทดสอบต่อ | หลักฐานส่งกลับ |
|---|---|
| **Fleet simulation** ให้รถหลายคันขอใช้ประตูพร้อมกัน ปิดประตูระหว่างวางแผน ทำให้สถานะรถหนึ่งคันค้าง และทดสอบทางแคบ/วงกวาดประตูบานพับ | Log ตำแหน่งและคิวรายคัน ช่วงจองทาง เวลารอ การเปลี่ยนเส้นทาง และผลตรวจว่าช่วงห้ามใช้ร่วมกันไม่ทับกัน |
| **ML เวลารอ AMR** จับเวลาตั้งแต่เข้าคิวจนได้ใช้ทรัพยากร เช่น ประตูหรือทางแคบ เก็บจำนวนรถในคิวและสถานะประตู เทียบกับค่ามัธยฐานบนข้อมูลคนละช่วงกับชุดฝึก | ตารางค่าจริง ค่าทำนาย และความคลาดเคลื่อนเป็นวินาที บน Dashboard ค่าทำนายใช้แสดงเวลารอ ระบบจองทางใช้สถานะจริง ทดสอบแขน UR และการทำนาย OCC ภายหลัง |
| **LINE Alarm และ LLM** ให้ Node-RED ส่ง Alarm จากเหตุการณ์จำลอง และให้ LLM ตอบคำถามสถานะจากข้อมูลที่ Node-RED อ่านได้ ทดสอบข้อมูลสด ข้อมูลค้าง และ ID รถที่ไม่มี | ตัวอย่าง Alarm หนึ่งเหตุการณ์พร้อมเวลาที่ส่ง ตัวอย่างคำตอบที่ระบุรถและเวลาอัปเดต และกรณีข้อมูลไม่พอ ยืนยันว่าเส้นทางของ LLM เปิดใช้อ่านสถานะอย่างเดียว |
| **Backup / Restore** โหลดชุด Floor 9 จาก Git ลงสภาพแวดล้อมแยกและ import Map Reference flow | เทียบ `referenceId` ขนาดภาพ ตำแหน่งวัตถุ และผล Tap-to-Go ก่อน–หลัง พร้อมบันทึกรุ่นที่กู้คืน |
