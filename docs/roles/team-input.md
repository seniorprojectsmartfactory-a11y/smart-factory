# ข้อมูลที่ขอจากทีมเพื่อแบ่งหน้าที่

กรอกหนึ่งแถวต่อสมาชิก ใช้ชื่อเล่นได้ ถ้ายังเลือกงานไม่ได้ให้เว้นช่องไว้

| ชื่อ | ระบบหรือไฟล์ที่ทำอยู่ | สิ่งที่อยากรับผิดชอบ | ผลงานที่คิดว่าจะส่งได้ | เข้า Lab ได้ช่วงไหน |
|---|---|---|---|---|
| ตัวอย่าง A | Node-RED อ่าน WISE และส่งเข้า InfluxDB | หลังบ้านและ API สำหรับ Live Map | Flow ที่ export ได้ ตัวอย่าง JSON และผลทดสอบ API | วันศุกร์ช่วงบ่าย |
| ตัวอย่าง B | จัด panel ใน Grafana | UX/UI หน้า Dashboard และ Live Map | ภาพร่างหน้าจอ Dashboard JSON และหน้าที่แสดงสถานะ offline | ทำจากนอก Lab ได้ |
| | | | | |

## แต่ละตำแหน่งลงมือทำอะไร

| ตำแหน่ง | ตัวอย่างงานที่ทำในโปรเจกต์นี้ | สิ่งที่ส่งให้ทีม |
|---|---|---|
| [Automation / หลังบ้าน Node-RED](automation.md) | รับสัญญาณ WISE จาก Modbus อ่านสถานะ MiR/UR แปลงค่า ใส่เวลา และเขียนเข้า InfluxDB ดูแล API และข้อมูลที่หน้า Live Map ใช้ รวมถึงกรณีอุปกรณ์ไม่ตอบ | Flow ที่ export ได้ ตัวอย่าง payload/API ระบุ field และผลทดสอบกรณีปกติกับ timeout |
| [IIoT / อุปกรณ์จริง](iiot.md) | ตรวจสายและช่อง DI/DO/AI ของ WISE ตรวจเครือข่ายและ Modbus จากเครื่อง Lab แล้วเทียบค่าที่อ่านได้กับสัญญาณจริง | ตารางอุปกรณ์ ช่อง I/O, Modbus address, หน่วย และตัวอย่างค่าที่ตรวจแล้ว |
| [SIM / ข้อมูลจำลอง](simulation.md) | ทำตัวสร้างค่า Analog Input ของ WISE-4012 และสถานะ AMR จำลอง เตรียมกรณีค่าปกติ ค่าเปลี่ยน และหยุดส่งข้อมูลให้คนอื่นทดสอบนอก Lab | Flow หรือชุดข้อมูลจำลอง วิธีเปิด–ปิด และผลที่คาดของแต่ละกรณี |
| [Database / InfluxDB](database.md) | กำหนดชื่อ measurement, field, tag และชนิดข้อมูล ดูแล bucket, query, สิทธิ์อ่านเขียน และสำรองข้อมูล ตกลงรูปแบบข้อมูลก่อนเปลี่ยน schema | ตาราง schema, query ตัวอย่างที่ทดสอบแล้ว และหลักฐานสำรองหรือกู้คืน |
| [Dashboard / UX/UI และ Live Map](dashboard.md) | กำหนดว่าผู้ใช้ต้องเห็นอะไรเป็นอันดับแรก วางหน้า Fleet Overview, Sensor Monitoring และ Live Map เลือกกราฟ การ์ด สี หน่วย ตัวกรอง และข้อความตอนข้อมูลค้างหรือไม่มีข้อมูล แล้วนำไปทำจริงใน Grafana หรือหน้า Live Map | ภาพร่างหรือ wireframe รายการ panel กับ query, Grafana JSON หรือไฟล์หน้าเว็บ และภาพทดสอบหน้าจอ |
| [Robotics / AMR Route Lab และ UR](robotics.md) | ดูแลข้อมูลหุ่นยนต์และแผนที่ของ Route Lab ตรวจ robot ID, map ID และกรอบพิกัดกับเครื่อง Lab ประสานผู้ควบคุม Lab เพื่อทดสอบกับ AMR หรือ UR | รายการอุปกรณ์และแผนที่ที่ยืนยันแล้ว พร้อมผลทดสอบ Route Lab และข้อจำกัดหน้างาน |
| [Infrastructure / Docker และ GitHub](infrastructure.md) | ดูแล Compose, พอร์ต และการเริ่มบริการ จัดวิธีส่งโค้ดผ่าน branch และ pull request และเตรียมขั้นตอนสำหรับสมาชิกที่ทำงานจากเครื่องอื่น | ไฟล์ Compose, คู่มือเปิดระบบและตรวจสถานะ และรายการไฟล์ที่เผยแพร่ได้ |
| [Integration / QA และ Demo](integration-qa.md) | ทดสอบตั้งแต่เซนเซอร์ถึงกราฟ ตรวจว่าค่าและเวลาตรงกัน ทดลองกรณีอุปกรณ์ออฟไลน์ และซ้อมเดโมตามลำดับ | ตารางผลทดสอบ ภาพหรือบันทึกผล และรายการปัญหาพร้อมคนรับช่วง |

## ตัวอย่างการแบ่งงานหลังบ้านกับหน้า UX/UI

**หลังบ้านของผม** หากคุณรับงานนี้ ให้ระบุว่าส่วนใดคุณดูแลเอง เช่น Node-RED, API ของ Live Map, การเขียนและ query InfluxDB หรือ Docker คนทำหลังบ้านส่งให้คนทำหน้าจอว่าเรียกข้อมูลที่ไหน มี field อะไร ใช้หน่วยอะไร และบอกว่าออนไลน์หรือข้อมูลค้างอย่างไร

**หน้า UX/UI Dashboard** ให้ระบุว่าใครออกแบบและใครลงมือทำใน Grafana หรือหน้า Live Map เช่น หน้า Fleet ควรเห็นชื่อหุ่น สถานะ แบตเตอรี่ และเวลาข้อมูลล่าสุด ส่วนหน้า Sensor Monitoring ควรเห็นสถานะตรวจจับ จำนวนชิ้น และกราฟย้อนหลัง เมื่อข้อมูลหยุดอัปเดตให้กำหนดว่าหน้าจอจะแสดงอะไร คนทำ UX/UI ส่งภาพร่างให้ทีมตรวจ แล้วส่ง dashboard หรือหน้าเว็บที่ทำเสร็จพร้อมหลักฐานการทดสอบ

**ตัวอย่างจุดส่งงานระหว่างสองคน** หลังบ้านส่งตัวอย่างข้อมูล AMR หนึ่งคันพร้อมเวลาและสถานะ คนทำหน้าจอนำไปทำการ์ดและ marker จากนั้นทั้งสองคนทดสอบร่วมกันว่าข้อมูลใหม่แสดงถูกคันและหน้าจอแยกสถานะข้อมูลค้างได้

## ข้อมูลที่อยากให้ตอบกลับ

1. **ทีมมีกี่คนและแต่ละคนทำอะไรอยู่แล้ว?** กรอกตารางด้านบน หรือส่งแบบ `ชื่อ — งานที่ทำอยู่ — งานที่อยากรับ — ผลงานที่จะส่ง`
2. **คุณทำหลังบ้านถึงส่วนไหนแล้ว และอยากเป็นเจ้าของส่วนไหนต่อ?** ระบุระบบหรือไฟล์ที่ทำ เช่น flow Node-RED, API Live Map, InfluxDB หรือ Docker และจุดที่อยากส่งต่อให้คนอื่น
3. **ใครรับ UX/UI และหน้าไหนบ้าง?** ระบุว่าเขาออกแบบอย่างเดียวหรือทำใน Grafana/Live Map ด้วย และหน้าไหนต้องเสร็จก่อน
4. **ใครเข้า Lab ได้ และวันเดโมต้องแสดงอะไร?** ระบุคนที่ทดสอบอุปกรณ์จริงได้ ช่วงเวลาโดยคร่าว และงานที่ยังไม่มีเจ้าของ

คนหนึ่งรับได้หลายตำแหน่ง เมื่อได้ข้อมูลแล้วจะจัดตารางผู้รับผิดชอบหลัก ผู้สำรอง และงานส่งมอบของแต่ละคน
