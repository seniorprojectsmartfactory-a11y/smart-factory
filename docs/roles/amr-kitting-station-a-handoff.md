# Capstone — Handoff ไลน์แพ็กของและตรวจด้วยกล้องที่สถานี A

จาก YUI / Woray ถึง AI ใน Lab และทีม Robotics · อัปเดต 25 พฤศจิกายน 2026

**สถานะ** เดโมรอบแรกให้ UR แพ็กของลงกล่องบน AMR โดยตรง ใช้ RealSense D435i และ OpenCV บน Windows ตรวจชนิดและจำนวนก่อนปิดฝา ต้นแบบตรวจภาพจำลองผ่านการทดสอบบน Windows แล้ว รอยืนยันภาพสี ความสูงกล้อง การจอดซ้ำ และการคีบฝาจากอุปกรณ์จริงใน Lab

**เจ้าของงานกล้องและ Vision QC** คือ Woray ฝั่ง [Automation](automation.md) รับผิดชอบตั้งกล้อง ปรับ OpenCV ทดสอบ QC และส่งผลเข้า Node-RED / หน้าเว็บ ส่วน [Robotics](robotics.md) ส่งสถานะรถจอดพร้อมและแขนถอนพ้นกล้อง รวมถึงดูแลการปิดฝาและการเคลื่อนที่ของรถร่วมกับผู้ควบคุม Lab

## เดโมหลัก

ใช้ **UR ตั้งโต๊ะประจำ A หนึ่งตัว** และ **AMR ขนส่งที่ไม่มีแขนหนึ่งคัน** ให้ AMR จอดพร้อมกล่องพลาสติกเปล่าที่มีตำแหน่งรับคงที่บนพื้นบรรทุก UR หยิบชิ้นงานจากโต๊ะป้อนลงกล่อง ตรวจด้วยกล้อง แล้วปิดฝาและส่งไปจุดรับ รอบเดโมจบเมื่อรถจอดถึงปลายทางพร้อมกล่อง

| ออเดอร์ | บล็อกสีส้ม | แหวนสีน้ำเงิน |
|---|---:|---:|
| Set A | 3 | 0 |
| Set B | 2 | 1 |

1. ผู้ใช้กด Set A หรือ Set B บนเว็บ ระบบผูกรหัสออเดอร์กับสูตรและใช้สูตรเดิมจนจบรอบ
2. เมื่อรถจอดนิ่งและกล่องพร้อม UR-A วางของลงกล่องตามสูตร ใช้จุดวางหลวม ๆ สามตำแหน่งให้กล้องเห็นแต่ละชิ้นจากด้านบน
3. หลัง UR ถอนแขนพ้นภาพ ให้กล้องถ่ายก่อนปิดฝาและตรวจชนิดกับจำนวน ถ้าของขาด เกิน ผิดชนิด ภาพอ่านไม่ได้ หรือกล้องขัดข้อง ให้ค้างกล่องเปิดไว้ที่ A และแสดงเหตุผลบนเว็บ
4. เมื่อ QC ผ่าน ให้ UR วางฝาครอบ ใช้ฝาที่มีขอบนำและจุดจับสำหรับลองกับมือคีบรอบแรก ยืนยันฝาเข้าที่และแขนพ้นจุดจอดก่อนปล่อยรถไปจุดรับที่ปลายทาง วิธีตรวจฝาให้ยืนยันใน Lab แยกจากการตรวจของในกล่อง
5. บันทึกรหัสออเดอร์ ผลตรวจและจำนวนที่เห็น ภาพตรวจ ผลยืนยันฝา และผลถึงปลายทาง

## ผังและอุปกรณ์ที่ต้องยืนยัน

ถ่ายรูปด้านข้างให้เห็นฐาน UR โต๊ะยาว และรถตอนจอดหน้าโต๊ะ จากนั้นถ่ายมุมสูงให้เห็นพื้นที่จอดและพื้นที่หลังแขน วัดความสูงผิวโต๊ะและพื้นบรรทุกจากพื้นเดียวกัน วัดระยะในแนวราบจากฐาน UR ถึงจุดวางของในกล่อง จุดหยิบฝา และจุดป้อนด้านหลัง ระบุรุ่น UR มือคีบ AMR และขนาดกล่องกับฝา ให้ผู้ควบคุม Lab ทบทวนจุดจอดและแนวเคลื่อนแขนก่อนทดลองเคลื่อนที่จริง

พื้นที่ด้านหลัง UR เป็นตำแหน่งเสนอสำหรับจุดป้อนหรือพักกล่องเปล่า หลังตรวจแนวเคลื่อนแขนแล้ว ถ้ากล้องหรือแขนเข้าไม่ถึงกล่องบนรถอย่างสม่ำเสมอ ให้ทดลองแพ็กและตรวจบนโต๊ะ แล้วประเมินว่ามือคีบยกกล่องเต็มลงรถได้หรือไม่

## ขั้นตั้งกล้องและทดสอบ QC บน Windows

เปิด [คู่มือตั้งกล้องพร้อมคำสั่ง PowerShell](../station-a-camera-setup-windows.md) สำหรับปฏิบัติใน Lab รวมถึงวิธีบันทึกภาพนิ่งและกำหนดกรอบตรวจ

| ขั้น | วิธีทำ | เกณฑ์ผ่าน |
|---|---|---|
| **1. เปิดสตรีมสี** | ต่อ D435i ผ่าน USB บน Windows เปิด RealSense Viewer แล้วเช็ก Color ที่ `640 × 480` ให้ตรงกับต้นแบบ | ภาพสีต่อเนื่องและเห็นสีชิ้นงานจริง |
| **2. ลองความสูงและมุม** | ตั้งกล้องชั่วคราวให้มองลงกลางกล่องบนรถ ลอง 2–3 ระดับ เช่น 40, 50, 60 ซม. วัดจากหน้ากล้องถึงพื้นในกล่อง ลองวางชิ้นงานทั้งกลางกล่องและใกล้มุม | เห็นพื้นกล่องครบ มีขอบเผื่อการจอดคลาด และยังแยกรูแหวนกับขอบบล็อกได้ |
| **3. เช็กความคมและล็อกกล้อง** | ใช้ตารางหมากรุกวางราบในกล่องดูความคมกลางภาพและมุมภาพ แล้วดูชิ้นจริงซ้ำ จัดแสงคงที่และลองให้รถกลับมาจอดใหม่ | ขอบกล่องและชิ้นงานยังเห็นชัดในตำแหน่งจอดที่ทำซ้ำได้ |
| **4. ตรวจภาพนิ่ง** | ถ่ายกล่องเปล่า, A ถูก, B ถูก, ของขาด, ของเกิน, ผิดชนิด และของซ้อน กำหนด `ROI` สำหรับพื้นกล่อง แล้วปรับช่วงสี HSV และช่วงพื้นที่ของกลุ่มพิกเซลด้วยภาพชุดแรก ทดสอบด้วยภาพอีกชุด | จำนวนและชนิดตรงของจริง กล่องผิดในชุดทดสอบไม่หลุดเป็นผ่าน |
| **5. ตรวจภาพสด** | จับภาพหลังแขนถอนพ้นภาพและก่อนปิดฝา ลอง A, B และกล่องผิดจากการจอดหลายรอบ บันทึกภาพกับผลตรวจตามออเดอร์ | สถานีค้างฝาและรถเมื่อผลตรวจไม่ผ่าน และส่งกล่องที่ผ่านถึงปลายทางได้ในรอบที่ Lab อนุมัติ |
| **6. ตัดสินใจเรื่องโมเดล** | ใช้ OpenCV ต่อเมื่อผลทดสอบผ่าน ถ้ายังสับสนเพราะชิ้นงานสีคล้ายหรือรูปแบบเปลี่ยนบ่อย ให้เก็บภาพจริง ตีป้าย `block` / `ring` รายชิ้น และแยกชุด train กับชุดทดสอบ ถ้าเครื่อง Solomon มี SolVision พร้อมใช้ ให้เทียบด้วยกล่องและชุดทดสอบเดียวกัน | มีผลเปรียบเทียบว่าทางเลือกใหม่ช่วยแก้ข้อผิดพลาดใด ถ้าชิ้นงานถูกบังมิด ให้แก้จุดวางหรือมุมกล้องก่อน |

ตารางหมากรุกในขั้น 3 ใช้เป็นลายอ้างอิงดูความคม วัดระยะติดตั้งด้วยตลับเมตร หากต้องแก้ภาพบิดหรือคำนวณตำแหน่งจริง ให้ทำ camera calibration ด้วยตารางที่รู้ขนาดช่องและภาพจากหลายมุม [OpenCV — Camera Calibration](https://docs.opencv.org/4.13.0/dc/d43/tutorial_camera_calibration_square_chess.html)

### ต้นแบบและผลที่มี

- ต้นแบบอยู่ใน workspace ForAI ที่ `Capstone/vision/packing-qc/` มี `packing_qc.py`, `inspection.json` และ `README.md` ใช้ Python 3.12 บน Windows จับภาพสีจากกล้องด้วย `--camera --capture-only` เริ่มปรับเกณฑ์ด้วย `--image` แล้วค่อยใช้ `--camera --recipe A` หรือ `B` พร้อม `--roi X Y W H` โดยพิกัดวัดจากภาพจริง โค้ดอยู่ใน workspace นอก repo นี้
- ต้นแบบส่ง `PASS`, `FAIL`, `HOLD` หรือ `ERROR` เป็น JSON และบันทึกภาพตีกรอบได้ ผลที่มีคือทดสอบด้วยภาพจำลองบน Windows ผ่าน 8 กรณี การจับภาพจากกล้องจริงและค่าช่วงสียังรอยืนยันใน Lab
- ชิ้นสีเดียวกันที่แตะกันอาจถูกนับรวม และวัตถุที่สีอยู่นอกช่วงอาจไม่นับ ให้จัดพื้นที่วางให้เห็นแต่ละชิ้นและทดสอบกรณีเหล่านี้ก่อนใช้ผล QC เพื่อควบคุมไลน์

**สิ่งที่ให้ AI ใน Lab ส่งกลับ** รูปและระยะกล้องที่เลือก พิกัด ROI ภาพดิบและภาพตีกรอบของกล่องถูกและกล่องผิด ผลจอดซ้ำ ผลลองมือคีบฝา และรายการเคสที่ตรวจผิด พร้อมแยกผลจากภาพจำลองกับผล Lab จริง

## บทบาทของ AMR ติด UR

เป็นเดโมต่อยอดสำหรับปลายทางที่ไม่มีแขนประจำ ให้ AMR ติด UR รับกล่องที่ผ่านและปิดฝาจาก A แล้วให้แขนบนรถยกลงโต๊ะปลายทางหลังรถจอด
