# ส่งต่องาน Joystick สำหรับ AMR Route Lab

22 พฤศจิกายน 2569 · จาก YUI และ Yamato · สำหรับผู้ดูแล AMR และ Node-RED ใน Lab

เป้าหมายคือให้ผู้ควบคุมที่อยู่หน้างานและมองเห็นรถ เลือก AMR หนึ่งคันแล้วใช้ joystick ขยับรถระยะสั้นเพื่อปรับจุดจอดหรือพาออกจากจุดติด ก่อนเขียนตัวเชื่อมกับรถจริง ให้ยืนยันช่องทางควบคุมจากเอกสารของรุ่นและ firmware ของคันที่จะทดสอบ

## ลำดับการใช้งานบน Dashboard

1. Dashboard แสดง AMR 1, AMR 2 และ AMR 3 พร้อมกันบนแผนที่และในรายการ ผู้ควบคุมเลือกคันที่ต้องการจากตำแหน่งใดตำแหน่งหนึ่ง
2. เมื่อกด **Joystick** แผงควบคุมเปิดขึ้นพร้อมแสดงชื่อหรือ ID ของคันที่เลือก เช่น **Joystick · AMR 1** และผูกกับคันนั้นทันที ผู้ควบคุมเลือกคันเพียงครั้งเดียว
3. หากคันที่เลือกพร้อมและได้รับสิทธิ์แล้ว ผู้ควบคุมกดค้างเพื่อขยับรถได้เลย การเปิดแผงอย่างเดียวไม่มีคำสั่งเคลื่อนที่ ถ้ารถไม่พร้อมหรือมีคนอื่นคุมอยู่ ให้แสดงเหตุผลบนแผง
4. แผงหนึ่งคุมได้ทีละคัน หากเปลี่ยนจาก AMR 1 ไป AMR 2 ให้สิ้นสุดการควบคุมคันเดิมและปิดแผงเดิม เปิดแผงใหม่ด้วยปุ่ม **Joystick** เพื่อเริ่มคุม AMR 2

## ต้นแบบสำหรับรีวิวหน้าจอ

- Import [Node-RED flow](../../node-red/amr-lab/amr-joystick.flow.json) ผ่านเมนู Import แล้วกด Deploy จากนั้นเปิด /amr/joystick บน Node-RED ของเครื่องนั้น แท็บชื่อ **Capstone AMR Joystick** และแสดงการเคลื่อนที่จำลองในเบราว์เซอร์
- [โค้ดหน้าเว็บ](../../amr-route-lab/joystick-preview.html) คือ HTML สำหรับแก้และทดสอบหน้าจอ ตัวส่งมอบ Node-RED ฝัง HTML และภาพผังชั้น 9 อยู่ใน Template ชื่อ **หน้า Joystick AMR จำลอง** เมื่อแก้ Template ผ่าน Editor ให้ Export แท็บนี้กลับเข้า GitHub เพื่อให้ทีมได้ flow รุ่นเดียวกัน
- ตรวจในเบราว์เซอร์แล้วว่าเลือก AMR 1–3 และเปิดแผงผูกกับคันที่เลือกได้ กดค้างแล้วขยับเฉพาะคันนั้น ปล่อยแล้วหยุด และเปลี่ยนคันแล้วแผงเดิมปิด การตอบสนองของรถจริงรอทดสอบใน Lab
- ชุดนี้พร้อมให้ทีมลองเลือกคัน เปิดแผง และขยับ AMR จำลองบนผัง

## สถานะตอนส่งต่อ

- Node-RED บนเครื่องพัฒนารันที่ `127.0.0.1:1884` แท็บ **Capstone AMR Route Editor** เป็นหน้าวางเส้นทางด้วยตำแหน่งรถจำลอง ส่วนแท็บเดิมจาก GitHub ถูกโหลดไว้สำหรับตรวจ flow
- ใน GitHub `main` ที่ตรวจไว้ (`35795ca`) มี Live Map และการอ่านสถานะ MiR ใน `node-red/flows.json` ส่วน `amr-route-lab/server.cjs` จัดการส่งภารกิจแบบจุดเป้าหมาย ช่องทางส่งภารกิจนี้มีหน้าที่ต่างจากการขับด้วย joystick ต่อเนื่อง
- คู่มือ MiR200 v3.1 อธิบาย joystick ใน Manual Mode ผ่านหน้า MiR และกำหนดให้มีผู้ควบคุมทีละคน คู่มือนี้ยังไม่ยืนยันช่องทางสำหรับ joystick จากแอปภายนอกใน firmware ของรถใน Lab และยังไม่มีผลทดสอบการเชื่อม joystick กับรถจริงของทีม [คู่มือ MiR200 หน้า 16 และ 41](https://d18hjk6wpn1fl5.cloudfront.net/public/187/documents/Current-mir200_user_guide_3_1_en_pdf-187-50846-1.pdf)

## สิ่งที่ต้องยืนยันใน Lab

1. **เลือกหุ่นหนึ่งคัน** แล้วบันทึกรุ่น ID ภายในทีม และ firmware ที่หน้าหุ่นแสดง ใช้ข้อมูลของคันจริงเป็นหลัก เพราะบันทึกเดิมมีหลายเวอร์ชัน
2. **ขอเอกสาร interface สำหรับ Manual Control ของรุ่นนั้น** ให้ผู้ดูแล Lab ดูจากเอกสารที่มากับรถหรือสอบถาม MiR Support ว่ารองรับการใช้ joystick จากแอปภายนอกหรือไม่ หากรองรับ ให้เก็บเอกสารส่วนที่ระบุวิธีขอและคืนสิทธิ์ควบคุม เงื่อนไขเข้าโหมด Manual และพฤติกรรมเมื่อปล่อยการควบคุมหรือการเชื่อมต่อขาด [MiR Support Portal](https://mobile-industrial-robots.com/support-portal)
3. **ส่งคำตอบกลับให้ทีมสองข้อ** ช่องทางภายนอกที่รองรับพร้อมเอกสารอ้างอิง และเงื่อนไขสำหรับการทดลองกับรถหนึ่งคัน หาก MiR รองรับเฉพาะ joystick ใน Robot Interface ให้ Dashboard แสดงสถานะและพาผู้ควบคุมไปยังหน้า MiR ของคันที่เลือก

## งาน Node-RED หลังยืนยันช่องทาง

เมื่อได้เอกสารของรุ่นจริง ให้ Yamato ต่อ flow joystick ใน Node-RED instance เดิมกับช่องทางที่ MiR รองรับ แล้วให้ UI แสดงสถานะรถและสิทธิ์ควบคุมจากหลังบ้าน รวมถึงเหตุผลเมื่อเข้าโหมดควบคุมไม่ได้หรือสิทธิ์สิ้นสุด

| กรณีทดสอบ | ผลที่ต้องเห็น |
|---|---|
| เลือก AMR 1 แล้วกด Joystick | แผงเปิดพร้อมชื่อ AMR 1 โดยไม่ให้เลือกซ้ำ เมื่อรถพร้อมและผู้ใช้กดค้าง คำสั่งต้องไปถึง AMR 1 เท่านั้น |
| กดค้างและปล่อย joystick | เคลื่อนเฉพาะคันที่เลือกในช่วงได้รับสิทธิ์ และหยุดเมื่อปล่อย |
| ปิดแท็บ การเชื่อมต่อหลุด หรือสถานะรถไม่พร้อม | การควบคุมสิ้นสุดตามกลไกที่ MiR รองรับ การเชื่อมต่อกลับมาต้องขอเริ่มควบคุมใหม่ |
| สองคนขอคุมคันเดียวกัน หรือเปลี่ยนคันระหว่างคุม | มีผู้ควบคุมได้คนเดียว ต้องคืนสิทธิ์คันเดิมก่อนเริ่มควบคุมคันใหม่ |
| คันที่เลือกกำลังทำ Mission | หน้าจอแสดงสถานะและให้ผู้ควบคุมจัดการภารกิจตามขั้นตอนของ Lab |

ก่อนทดสอบกับรถจริง ให้ผู้ดูแล Lab ยืนยันการหยุดเมื่อสื่อสารขาดและกำกับการทดลองกับรถหนึ่งคัน โดยใช้โหมดควบคุมและระบบหยุดฉุกเฉินของ MiR ตามคู่มือ

## ไฟล์ที่อ่านก่อนเริ่ม

1. ข้อกำหนด Dashboard ฟังก์ชัน 1 และ 2 และบันทึก Fleet Intelligence เป็นเอกสารส่งต่อภายใน Capstone Lab ใช้ต่อเมื่อต้องตรวจประวัติการทดสอบและรายการ firmware
2. [Node-RED flows ของทีม](../../node-red/flows.json) สำหรับจุดเชื่อมสถานะรถ และ [หลังบ้าน Route Lab](../../amr-route-lab/server.cjs) สำหรับเส้นทางที่ใช้ส่ง Mission อยู่แล้ว
