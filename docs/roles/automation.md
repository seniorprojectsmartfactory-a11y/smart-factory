# Automation / Node-RED

**ผู้รับผิดชอบ** ____________________  
**ผู้สำรอง** ____________________

ดูแลเส้นทางข้อมูลจาก WISE-4012, WISE-4250, MiR และ UR จนถึงข้อความที่ Node-RED ส่งไปยังฐานข้อมูลหรือหน้าแสดงผล รวมถึงการตรวจกล่องด้วยกล้องที่สถานี A

## งานหลัก

- ใช้ Modbus mapping, หน่วย และชนิดข้อมูลที่ [IIoT](iiot.md) ยืนยันแล้วมาตั้งค่า flow และกำหนดรอบอ่านของ WISE
- ดูแล flow ตรวจจับและนับวัตถุ แยกสถานะปัจจุบันออกจากเหตุการณ์ที่เกิดขึ้น และบันทึกวิธีทดสอบการ reset counter
- ดูแล flow อ่านสถานะ MiR/UR และการจัดการ timeout, offline และ timestamp โดยให้การอ่านอุปกรณ์ตัวอื่นทำงานต่อเมื่อเครื่องใดเครื่องหนึ่งไม่ตอบ
- ตกลงชื่อ measurement, field, tag และชนิดข้อมูลกับ Database ก่อนแก้ output node ส่งตัวอย่าง payload ที่ตัดข้อมูลลับแล้วให้ Dashboard ใช้ทดสอบ

## กล้องตรวจ QC ที่สถานี A

**ผู้รับผิดชอบงานกล้องและ Vision QC คือ Woray (Automation)**

- ตั้ง RealSense D435i บน Windows เลือกมุม ความสูง และแสงร่วมกับทีม Lab ตั้งกรอบตรวจและปรับ OpenCV ด้วยภาพกล่องจริง
- ผูกสูตร Set A/B กับรหัสออเดอร์ รับสถานะรถจอดพร้อมและ UR จัดของเสร็จพร้อมถอนแขนพ้นภาพจาก Robotics แล้วจึงจับภาพก่อนปิดฝา
- ส่งผล `PASS`, `FAIL`, `HOLD` หรือ `ERROR` พร้อมรหัสออเดอร์ ผลนับ และเหตุผลให้ Node-RED / หน้าเว็บ ส่วนลำดับงานใช้ `PASS` ของออเดอร์ปัจจุบันเพื่อไปขั้นปิดฝา และรอการยืนยันฝาเข้าที่กับแขนพ้นจุดจอดก่อนส่งรถ
- Robotics รับผิดชอบท่าหยิบวางและปิดฝาของ UR รวมถึงการจอดและเคลื่อนที่ของ AMR ร่วมกับผู้ควบคุม Lab ตกลงจุดส่งสถานะกับ Automation ก่อนทดสอบทั้งไลน์

## ไฟล์ที่ใช้

- สำเนา flow ที่รันใน Docker อยู่ใน `infra/docker-migration/data/nodered/flows.json` ส่วนไฟล์ `flows_cred.json` และการตั้งค่าหน้างานเก็บไว้ในเครื่อง Lab
- รายงาน Modbus WISE-4012 (`WISE-4012_Node-RED_Modbus_Report_2026-09-16.md`)
- ระบบตรวจจับวัตถุ WISE-4012 (`Object-Detection-WISE4012.md`) และ รายงานทดสอบ DI1 (`EZ-18M-Integration-Report-2026-09-22.md`)
- [Handoff สถานี A](amr-kitting-station-a-handoff.md) สำหรับสูตรออเดอร์ ขั้นตั้งกล้อง และเกณฑ์ทดสอบ QC

## ส่งมอบเมื่อ

- Export flow ที่แก้ พร้อมระบุ tab, input, output และวิธีนำเข้า
- มีผลทดสอบอย่างน้อยหนึ่งกรณีที่รับค่าปกติและหนึ่งกรณีที่อุปกรณ์ไม่ตอบ พร้อมตัวอย่างค่าที่ Database ตรวจสอบต่อได้
- ระบุชัดว่าทดสอบด้วยข้อมูลจำลองหรืออุปกรณ์จริง และส่วนใดต้องให้ Robotics หรือผู้ควบคุม Lab ตรวจต่อ
- งานกล้องส่งมอบค่าตั้งและภาพจริงที่ใช้ทดสอบ พร้อมผล Set A/B และกรณีของขาด ผิดชนิด ภาพอ่านไม่ได้ หรือกล้องไม่ตอบ ตรวจว่ากรณีเหล่านี้ค้างก่อนปิดฝา
